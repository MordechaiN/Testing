## איך משתמשים

**הקבוצה השנייה לא מצטרפת?**
בראש כל מסך: "הקבוצה השנייה (זוג) מצטרפת?" ← **לא – רק קבוצה A**.
קבוצה B נעלמת מכל המסכים, והמחיר של קבוצה A **לא משתנה בכלל**. הנתונים של B נשמרים, ו"כן" מחזיר אותם.

**בחירת חדר**
במסך הסיכום, בשורה "חדר", לוחצים על החדר. אפשר גם במסך הזנת נתונים.
סוג החדר והמחיר מוצגים בנפרד. המערכת לא מניחה שחדר יקר יותר הוא טוב יותר, ולא בוחרת חדר בשבילכם.
עד שבוחרים, ההשוואה מחושבת לפי החדר הזול בכל תאריך ומסומנת 🟡 "השוואה חלקית".

**הוספת טיסה**
הזנת נתונים ← בחלק של הקבוצה ← "+ טיסת הלוך" / "+ טיסת חזור" / "+ כרטיס הלוך-חזור".
לכל טיסה: חברה, מספרי טיסה (הלוך וחזור), תאריכים, שעות, שדות, עצירות, משך, סוג תעריף, כבודה, תנאי שינוי וביטול, **מקור**, קישור ו**תאריך בדיקה**.
- **סה״כ העגלה:** אם מזינים "סה״כ הכרטיס כפי שמופיע בעגלה", זה מקור האמת. המערכת לא מחשבת מחדש לפי פירוט הנוסעים. הלוך-חזור (Round Trip) נספר פעם אחת בלבד.
- פירוט לכל נוסע (מבוגר 1, מבוגר 2, תינוק) משמש למידע. כשאין סה״כ עגלה, הוא מחושב מהפירוט.
- תינוק לא מחויב עד שמזינים לו מחיר. מושבים ומזוודות נספרים בנפרד.
- **מחיר מאומת:** סמנו "המחיר מאומת" רק אם ראיתם אותו באתר חברת התעופה או בעגלה. מחיר לא מאומת מוצג ב-🟡, לא מקבל ⭐ ולא משמש כהצעה ודאית.
- כל מחיר מוצג כ"מחיר שנבדק ב-תאריך", לא כמחיר מובטח.
- "העתק לקבוצה השנייה" משייך את אותה טיסה גם לקבוצה השנייה. אפשר להזין לה מחיר בפועל.
- 📌 **Benchmark:** טיסה להשוואה. אל-על $915.96 (03/09 → 14/09) כבר מוזנת כך, בדיוק לפי העגלה שהעתקתם. המערכת לא מדרסת אותה ולא מחליפה אותה אוטומטית בזולה יותר.

**דירוג טיסות (המלצה בלבד, עם הסיבה)**
- ⭐ **מומלץ:** ישירה, מרווח של יום-יומיים לפני הקרוז וגם אחריו, שעות סבירות, מחיר סביר, מחיר מאומת.
- 🟢 **מחיר טוב:** מחיר מאומת קרוב לזול ביותר מאותו סוג.
- 🟡 **פשרה:** עצירה, יותר מיומיים מרווח (לילות מלון נוספים), שעות פחות נוחות, מחיר גבוה ב-20% ויותר או מחיר לא מאומת. טיסה עם עצירה נשפטת בנפרד מישירה ומוצגת עם "זולה ב-$X מהישירה, אבל פחות נוחה".
- 🔴 **לא מומלץ:** הגעה ביום יציאת הקרוז, חזרה ביום הירידה, שתי עצירות ויותר, מחיר חריג (50% ויותר מעל הזולה).
- ⚪ **לא מדורג:** חסרים תאריכים או מספר עצירות. המערכת לא מנחשת.

**הוספת מלון**
הזנת נתונים ← "+ מלון חדש" בטופס הקבוצה, או "+ מלון לפני הקרוז" / "+ מלון אחרי הקרוז".
התאריכים המתוכננים (שני לילות לפני או אחרי הקרוז) מוזנים מראש ואפשר לשנות. מחיר לא מוזן מראש.
שדות: שם, כתובת, Check-in, Check-out (הלילות מחושבים לבד), מחיר ללילה, מסים, City tax, ארוחת בוקר, Resort fee, עלויות נוספות, קישור, מקור, תאריך בדיקה.
- **מטבע:** USD / EUR / ILS. מלון ביורו או בשקל מוצג בסכום שלו (למשל €300). **המערכת לא ממציאה שער.** מזינים בעצמכם "מחיר כולל לאחר המרה ל-USD", ורק אז הוא נכנס לסכום.
- אפשר לשמור כמה מלונות ולבחור את הנבחר בטופס הקבוצה. הבחירה משנה את הסכום.
- מלון שייך ל-A, ל-B או לשתיהן (50/50 או סכום ידני). מלון אחרי הקרוז הוא שורה נפרדת.
- "לא צריך מלון" נחשב החלטה, לא נתון חסר.

**טיפים, עמלה, משקאות, אינטרנט**
בטופס של כל קבוצה. טיפים אפשר להזין לכל הקבוצה או לאדם (× מספר אנשים).
שדה ריק מוצג כ-**"טרם הוזן"**, לא כ-$0. אם יודעים שהמחיר הוא 0, מזינים 0.

**תחבורה ועלויות אחרות**
"+ תחבורה" / "+ עלות אחרת". כל שורה כוללת מה, כמה, איזו קבוצה (או חצי-חצי) והערה.

**🏆 האפשרות המומלצת**
בראש מסך הסיכום, לכל קבוצה בנפרד: איזה תאריך מומלץ ולמה (טיסה ישירה, מרווח לפני ואחרי, מלון, מחיר הקרוז, מחיר כל הטיול).
כשחסר מידע (טיסות, מלון, טיפים, עמלה) מוצג **🟡 "עדיין מוקדם לבחור"** עם רשימת מה שחסר. תאריך שהטיסות שלו בדירוג 🔴 לא ימליצו עליו גם אם הוא הזול ביותר.

**מסלול**
בטבלת כל קבוצה: טיסה ← מלון ← קרוז ← מלון ← טיסת חזרה, לפי מה שנבחר.

**קרוז בלבד מול כל הטיול**
הטבלה מציגה את שניהם. אם הקרוז הזול יותר הוא לא החופשה הזולה יותר, מופיע על כך 🟡. ממוצע למבוגר מוצג כמידע משני בלבד.

**השוואת תאריכים**
במסך הסיכום, לכל קבוצה: סה״כ בכל תאריך ומשפט כמו **"19/09 זול ב-$795"**.
אם חסר מידע באחד התאריכים (טיסות, חדר, טיפים…), מופיע 🟡 **השוואה חלקית** עם הסיבות, ולא נטען שתאריך זול יותר בוודאות.

## איפה הנתונים נשמרים – ואיך מגבים

- הנתונים נשמרים **אוטומטית** בדפדפן שבו עובדים (localStorage), בכל שינוי. אין כפתור שמירה.
- רענון או סגירת הדפדפן לא מוחקים כלום. עדכון גרסה של האתר לא מוחק נתונים (גרסאות קודמות מומרות אוטומטית).
- הנתונים **לא** עוברים לבד בין מכשירים או דפדפנים.
- **ייצוא:** פרטים ותנאים ← "ייצוא נתונים (JSON)". יורד קובץ גיבוי.
- **ייבוא:** פרטים ותנאים ← "ייבוא נתונים" ← בוחרים את הקובץ. זה מחליף את הנתונים הנוכחיים (יש אישור לפני).

## למפתחים

React + TypeScript + Vite. אין שרת, אין מסד נתונים. דרוש Node.js 20 ומעלה.

```bash
npm ci
npm run dev          # שרת פיתוח
npm run typecheck    # בדיקת טיפוסים
npm run lint         # ESLint
npm test             # בדיקות (Vitest)
npm run build        # בונה ומעדכן את index.html בשורש הריפו
```

**מבנה**

```
src/index.html       דף המקור (ל-Vite)
src/domain/          חישובים, מצב, שמירה והמרת גרסאות – בלי UI
src/ui/              שלושת המסכים
tests/               בדיקות חישוב, בידוד קבוצות/תאריכים, שמירה, ייבוא/ייצוא, ממשק
scripts/             העתקת ה-build לשורש + בדיקת דפדפן מקצה לקצה
index.html           האתר המוכן (נוצר ע״י npm run build – לא לערוך ידנית)
.github/workflows/   בדיקה, בנייה ואימות GitHub Pages
```

**איך האתר עולה ל-GitHub Pages**

GitHub Pages מוגדר כ-"Deploy from a branch" ← `main`, `/ (root)`, ומגיש את `index.html` שבשורש.
`npm run build` מייצר קובץ HTML **יחיד** (JavaScript ו-CSS בתוכו), כך שאין נתיבי קבצים שיכולים להישבר תחת `/Testing/`. `.nojekyll` מונע עיבוד Jekyll.

בכל push ל-`main`, ה-workflow `Build & deploy to GitHub Pages`:
1. מריץ typecheck, lint, בדיקות ו-build.
2. מוודא ש-`index.html` שבריפו הוא בדיוק ה-build הטרי. אם שכחו להריץ build, הוא מתקן ומבצע commit בעצמו.
3. מחכה שהאתר החי יגיש בדיוק את הגרסה הזו (השוואת טביעת אצבע SHA-256).
4. מריץ בדיקת דפדפן אמיתית (Chrome) על האתר החי. הבדיקה בודקת:
   - שה-12 מחירים מוצגים, ושהתאריכים לא הפוכים.
   - תרחיש מלא: A = $7,392, B = $7,090.
   - שכיבוי B לא משנה את A.
   - שרענון שומר את הנתונים.
   - ייצוא וייבוא.
   - מובייל בלי גלילה לרוחב.
   - שאין שגיאות Console ואין 404.

אם יום אחד משנים ב-Settings ← Pages את ה-Source ל-"GitHub Actions", אותו workflow יעשה deploy דרך `actions/deploy-pages`, בלי שינוי קוד.

בדיקת הדפדפן מקומית (צריך `playwright-core` ו-Chrome):

```bash
node scripts/smoke-test.mjs https://mordechain.github.io/Testing/
```
